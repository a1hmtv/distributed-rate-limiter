# Rate Limiting System — микросервисная система ограничения запросов

## 🎯 Цель работы

Разработать микросервисную систему управления пользователями с механизмом ограничения количества запросов в минуту (RPM), динамическим обновлением лимитов и автоматической блокировкой пользователей при их превышении.

---

## 📦 Основные компоненты

1. **UserService — управление пользователями**
   - CRUD-операции через gRPC: `CreateUser`, `GetUserById`, `GetUserByName`, `UpdateUser`, `DeleteUser`.
   - Хранение данных в PostgreSQL.
   - Проверка уникальности логина.
   - Проверка заголовка `user_id` и блокировок через gRPC Interceptors.

2. **Writer — управление ограничениями**
   - CRUD-операции: `CreateLimit`, `GetLimitByRoute`, `UpdateLimit`, `DeleteLimit`.
   - Хранение ограничений в коллекции `rate_limits` в MongoDB.
   - Настройка допустимого RPM для каждого эндпоинта.

3. **Reader — контроль частоты запросов**
   - Загрузка ограничений в память батчами по 1000 элементов.
   - Динамическое обновление лимитов через MongoDB Change Streams.
   - Обработка событий из Apache Kafka.
   - Блокировка пользователей через Redis на 5 минут при превышении RPM.
   - Получение текущих ограничений через `GetAllLimits`.

4. **Kafka Event Generator — генератор событий**
   - Симуляция запросов от нескольких пользователей.
   - Настройка эндпоинтов и индивидуальной частоты запросов.
   - Динамическое изменение параметров без перезапуска приложения.

---

## ⚙️ Принцип работы

1. Writer создаёт ограничение и сохраняет его в MongoDB.
2. Reader получает изменения и обновляет ограничения в памяти.
3. Генератор отправляет события пользовательской активности в Kafka.
4. Reader проверяет количество запросов для каждой пары пользователь–эндпоинт.
5. При превышении RPM в Redis устанавливается флаг блокировки с TTL 5 минут.
6. UserService проверяет наличие блокировки и разрешает или отклоняет запрос.

## 🛠️ Стек технологий

- **C# / .NET** — разработка микросервисов.
- **gRPC** — API сервисов.
- **PostgreSQL + Dapper** — хранение пользователей.
- **MongoDB** — хранение и обновление ограничений.
- **Apache Kafka + Confluent.Kafka** — обработка событий.
- **Redis** — хранение временных блокировок.
- **Mapperly + FluentValidation** — маппинг и валидация.
- **Docker** — развёртывание Kafka.

---

## 🚫 Особенности реализации

- Три уровня моделей: `Request/Response`, `Domain`, `DbModel`.
- Асинхронная обработка с использованием `CancellationToken`.
- Потокобезопасное хранение ограничений.
- SQL-функции и процедуры в отдельных файлах директории `Database`.
- Разделение бизнес-логики и обработки сообщений Kafka.

## ❤️ Пример события Kafka

```json
{
  "user_id": 123,
  "endpoint": "GetUserById"
}
```

При установленном лимите в 15 RPM пользователь с частотой запросов 20 RPM будет заблокирован на 5 минут, а пользователь с частотой 10 RPM продолжит работу без ограничений.
